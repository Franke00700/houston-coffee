# Архитектура Houston Coffee

## Стек

- Node.js 24 LTS (локально 24.22.1).
- Next.js 16.4.4, App Router, TypeScript 5.9, React 19.3.1.
- PostgreSQL 18 в локальном Docker Compose; Prisma ORM 7.10.1 с `@prisma/adapter-pg`.
- Zod 4 для DTO, Argon2id для паролей, Vitest для доменных тестов.

Next.js требует Node.js 20.9+, Prisma 7 поддерживает Node 24; выбранная локальная версия удовлетворяет обоим требованиям. Prisma 8 на дату проектирования ещё RC, поэтому зафиксирован стабильный Prisma 7.

## Границы

```text
Браузер посетителя
  ├─ брендовая главная и меню
  ├─ локальная корзина (не источник цены)
  └─ public API: menu → quote → orders
                    │
Next.js server ─────┼─ доменные правила / RBAC / идемпотентность
                    ├─ PostgreSQL: каталог, настройки, заказы, sessions, audit
                    └─ изображения: локально только в dev; object storage до production
                    │
Браузер сотрудника ─┴─ admin UI/API, HttpOnly session + CSRF + Origin
```

## Доменные инварианты

- Клиент отправляет IDs и количество, но не доверенную цену.
- Quote и заказ рассчитываются сервером из опубликованных доступных сущностей.
- Деньги хранятся целыми копейками и с кодом валюты.
- Каждая строка заказа хранит snapshot названий, выбранных опций, unit price и totals.
- Изменение или архивирование меню не меняет историю заказа.
- `Idempotency-Key` уникален; hash нормализованного payload определяет повтор (`200/201`) или конфликт (`409`).
- Номер заказа удобен человеку, но не даёт гостевого доступа к PII.
- Переходы статусов задаются серверной state machine.
- Журнал действий append-only через приложение.

## RBAC

| Действие | Оператор | Администратор |
|---|---:|---:|
| Заказы: просмотр и допустимые статусы | Да | Да |
| Наличие | Да | Да |
| Каталог, цены, опции, изображения | Нет | Да |
| Контакты, расписание, доставка | Нет | Да |
| Сотрудники и роли | Нет | Да |
| Просмотр аудита | Нет | Да |
| Изменение аудита | Нет | Нет |

## Сессии и запросы

- Публичной регистрации сотрудников нет.
- Пароль: Argon2id; session token случаен, в БД хранится SHA-256 hash.
- Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` в production; idle и absolute expiry.
- После входа выдаётся новая сессия; logout/блокировка/смена роли отзывают её.
- Любая cookie-authenticated mutation проверяет роль, CSRF, `Origin` и JSON content type.
- Валидация DTO выполняется на границе; raw SQL не используется.

## Изображения

Разрешены JPEG/PNG/WebP с проверкой magic bytes, лимита файла и размеров. SVG и HTML запрещены. Перед production загрузки должны перекодироваться с удалением EXIF, сохраняться под случайным именем вне исполняемого каталога и отдаваться с `nosniff`.

## Производственные зависимости

- Общий Redis-compatible limiter нужен для нескольких экземпляров; in-memory limiter является только dev fallback.
- Object storage и reverse proxy настраиваются отдельно.
- Реальные платежи, сообщения и публикация не входят без отдельного разрешения.
