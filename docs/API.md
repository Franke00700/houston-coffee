# API-контракты

Все JSON DTO используют allowlist-поля. Ошибки возвращают стабильный `code`, человекочитаемое `message` и `requestId`, без stack trace и SQL.

## Публичные

### `GET /api/public/menu`

Возвращает опубликованные категории, доступные товары, разрешённые варианты/модификаторы и публичные настройки контактов/расписания/доставки. Неподтверждённые поля остаются `null` или не публикуются.

### `POST /api/public/quote`

Вход: позиции `{ productId, variantId?, modifierOptionIds[], quantity }`, способ получения и, для доставки, адресные данные. Выход: нормализованные строки, серверные цены, доставка, итог, предупреждения об изменениях.

### `POST /api/public/orders`

Обязательный header `Idempotency-Key`. Вход соответствует подтверждённому quote плюс минимальные гостевые контакты. Выход: номер, итог, способ получения и snapshot заказа. Тот же ключ и payload возвращают первый результат; другой payload — `409 IDEMPOTENCY_CONFLICT`.

Публичного `GET /orders/{number}` нет: последовательный номер не является секретом.

## Сотрудники

### `POST /api/admin/auth/login`

Rate limit по IP и нормализованному логину. Успех выдаёт HttpOnly cookie и CSRF token; сообщение об ошибке одинаково для неизвестного пользователя и неверного пароля.

### `POST /api/admin/auth/logout`

Требует session, CSRF и допустимый Origin; отзывает текущую сессию.

### Каталог и настройки

Admin-only CRUD для категорий, товаров, вариантов, модификаторов, изображений и публичных настроек. Удаление исторически используемых сущностей заменяется архивированием.

### Заказы

Admin/operator могут читать очередь и менять статус только по state machine. Конфликт версии или недопустимый переход возвращает `409`.

### Аудит и сотрудники

Только admin читает журнал и управляет сотрудниками/ролями. Audit mutation endpoints отсутствуют.
